## 5. คำตัดสินใหม่ (ต่อจาก D1–D4)
- **D5 ส่งต่อข้อความ = เมธอด `msg_<t>(p, m)` ในไฟล์ระบบเจ้าของ** แทนตาราง `dispatch.js`: `mix()` โยน error ถ้าสองระบบจับชนิดเดียวกัน (ตรวจเจ้าของให้ฟรี), เนื้อ case ย้ายแบบ verbatim ได้เพราะ `this` เดิม, ไม่มีตารางให้ลืมซิงก์ • `handle()` สุดท้าย = ด่าน `HOUSE_MSG` + ด่านถ้ำเดิม แล้ว `const f = this['msg_' + m.t]; if (typeof f === 'function') f.call(this, p, m);` • ห้ามใช้ prefix `msg_` กับอย่างอื่น
- **D6 act() คงห่วงโซ่ลำดับไว้** (ด่าน + เงื่อนไขทุกชั้น) ย้ายเฉพาะ**เนื้อ**ของแต่ละกิ่ง local ที่ใช้ร่วมส่งเป็น `c` และบรรทัดแรกของเมธอดคือ `const { … } = c;` • เรียกด้วย `return this.toolX(p, c)` ค่าคืนเหมือนเดิม
- **D7 event bus = ลำดับการเรียกที่เขียนชัดใน `event()`** ไม่ลงทะเบียนแบบไดนามิก เพราะลำดับ toast/XP/เหรียญ/`achCheck` คือพฤติกรรมที่ golden จับ ย้ายเฉพาะก้อน inline ไประบบเจ้าของ
- **D8 client = สคริปต์ธรรมดา ไม่ใช่ ES module** (ต่างจาก REFACTOR-PLAN): ปลด IIFE นอกสุดของ game.js ชื่อระดับบนจะอยู่ใน global lexical scope ที่ทุก `<script>` เห็นร่วมกัน แล้วตัดเป็นไฟล์โดยไม่แก้เนื้อ — ถ้าใช้ ES module ต้องแปลง `let` ระดับบน ~235 ตัวเป็น export/state = เขียนใหม่ และขัด D1 • `systems/*` มีแต่ `function` (ไม่มีคำสั่งที่รันตอนโหลด) และโหลด**ก่อน** main.js ลำดับคำสั่งตอนโหลดจึงเหมือนเดิม
- **D9 shared หลายไฟล์ = part** UMD ห่อฟังก์ชัน `(out, int) => {…}` • `shared/index.js` มี `PARTS` (ลำดับ = ลำดับข้อความเดิม) เรียกทีละ part แล้วประกอบ api จาก `EXPORTS` = รายชื่อใน `const api = {…}` เดิมเรียงเดิม (ชื่อภายในอยู่ `int` ไม่หลุดเข้า api) • Node require part / เบราว์เซอร์ part ลงทะเบียน `globalThis.__SHARED_PARTS[name]` แล้ว index.js ตั้ง `root.Shared` (ขาด/เกิน = throw) • สร้างออบเจ็กต์ใหม่ทุกครั้งที่โหลด index → `loadSharedWith` ล้าง cache แค่ index
