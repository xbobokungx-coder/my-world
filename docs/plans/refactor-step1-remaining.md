## 5. ขั้นตอน
**ประตูทุก commit** (ข้อที่รวมหลายไฟล์เล็ก = commit เดียว ถอยพร้อมกัน • จบข้อหยุดรอเจ้าของตรวจ)
1. เริ่ม `git pull` แล้ว `node tools/check-moved.js --snap <tmp>` ก่อนแตะโค้ด • ย้ายด้วย `tools/move-methods.js` ไม่ก๊อปมือ • ห้ามแก้เนื้อ เปลี่ยนชื่อ จัดรูปแบบ หรือแปลงเป็น arrow function
2. ไฟล์ระบบแบบ `lotto.js`: `'use strict'` + คอมเมนต์ + require เท่าที่ใช้ + `module.exports = { เมธอดเยื้อง 2 ช่อง }` **export เมธอดเท่านั้น** (mix ก๊อปทุก property) • เพิ่ม `mix(World, require(...))` ต่อท้ายบล็อก mix (ก่อน `module.exports` early return)
3. ตัวแปรระดับโมดูล: ใช้ระบบเดียว → ย้ายขึ้นบนสุดของไฟล์ระบบ • ใช้หลายที่ → `server/consts.js` • alias ของ shared (`SELLABLE = S.SELLABLE`, `rodOf`, `{ TS, T, CROPS, FISH, ANIMALS, SPAWN } = S`) ประกาศซ้ำในไฟล์ที่ใช้ได้ • `crypto` เรียกผ่าน `crypto.x()` เท่านั้น (golden แพตช์บน object โมดูล) • ห้ามเก็บ `Date.now`/`Math.random` ลงตัวแปรโมดูล
4. ผ่าน: `node --check` ไฟล์ที่แตะ • `tools/test-*.js` ทั้งหมด • golden โดยไม่ `GOLDEN_UPDATE` • `tools/check-structure.js` • `check-moved.js --cmp` เหมือนทุกเมธอด • รายชื่อตัวแปรโมดูลที่ move-methods พิมพ์ถูก require/ประกาศครบ • code-reviewer

## 6. ความเสี่ยงและการถอย
- ตัวแปรโมดูลหายในไฟล์ระบบ → ReferenceError เฉพาะตอนเส้นทางนั้นทำงาน (`node --check` และ golden อาจไม่เจอ) → รายชื่อของ move-methods ต้องปิดครบ; ระบบไม่มีเทสต์เฉพาะ (npc telemetry crafting events challenge village) reviewer ไล่ชื่อกับ require ทีละไฟล์
- ชื่อสับสน: `CAVE`/`S.CAVE`, `petPub`/`petPubOf`, `wk*` สามชุด, ชื่อกว้าง `pub other who finish count zone add event` (mix โยน error ถ้าซ้ำ ระบบใหม่ห้ามใช้ชื่อเหล่านี้)
- path require ผิดชั้นใน `arcade/` = โหลดไม่ขึ้น (เจอทันที) • เทสต์ห้าม require ไฟล์ระบบก่อน server.js (D3)
- ถอย: `git revert` commit ข้อนั้น (ข้อรวมหลายไฟล์ถอยพร้อมกัน) ไม่แตะเซฟ ไม่คืน data • deploy ตามคำตัดสินเจ้าของข้อ 3 (ช่วงคนน้อย, `deploy.sh --check` ก่อน) ไฟล์ใน `server/` ทำให้ restart ผู้เล่นหลุด
