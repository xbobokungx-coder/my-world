## 3. ออกแบบที่เก็บ (A)
- **แบบ "คลังรวมต่อชนิดตู้"** ไม่ผูกของกับตู้แต่ละใบ: เปิดตู้เย็นใบไหนก็เห็นคลังเย็นเดียวกัน ความจุ = ผลรวมความจุของตู้ชนิดนั้นที่วางอยู่ (นับสูงสุด `max` ใบ) → ไม่มีของติดกับเฟอร์นิเจอร์ ย้าย/หมุนตู้ไม่กระทบ
- ชนิด (ใช้เฟอร์นิเจอร์ที่มีอยู่ ไม่ต้องวาดใหม่): ❄️ **คลังเย็น** = `fridge` 60 ชิ้น/ใบ สูงสุด 4 ใบ รับเฉพาะ `S.perishable` อายุเดิน ×0.25 • 📦 **คลังของ** = `crate` 80, `cupboard` 60, `dresser` 60, `toolbox` 60, `barrel` 40, `nightstand` 20 สูงสุด 6 ใบ รับของไม่เสียที่ไม่ใช่ `once` (วัตถุดิบ ไม้ แร่ บาร์ เมล็ด อาหารสัตว์ เหยื่อ ตั๋ว อาหารซื้อ `meal_` เฟอร์นิเจอร์ที่ยังไม่วาง) • 🚪 คลังเสื้อผ้า (`wardrobe`) เลื่อนไป S8 (ต้องแก้จุดตรวจ "มีชุดนี้" `server.js:194,334` + ร้านกันซื้อซ้ำ)
- ห้ามเก็บ: `coin`, ของ `once` ทั้งหมด (เครื่องมือ/ยาน/สัตว์เลี้ยง/ตะเกียง — ระดับเครื่องมือคิดจาก `inv` ถ้าย้ายไประดับจะตก), ของที่ `itemInfo` เป็น null • ลังไม้/ตู้ส่วนใหญ่เป็นของช่างไม้ทำเอง → เพิ่มดีมานด์ช่างไม้
- **อายุในคลังเย็น ไม่คิดย้อนหลัง**: คลังเก็บ `r` (อัตราที่ใช้อยู่) และ `at` (จุดอ้างอิง) • อายุของกอง = `(at − tv) + (now − at) × r` (`S.storeAge` ใน shared) • ตอนเก็บ: อายุจริงในกระเป๋าแปลงเป็น `tv` • ตอนหยิบ: แปลงกลับเป็นเวลาได้ของในกระเป๋า `t = now − อายุ` → ของที่ออกมาแก่ต่อเท่าคนอื่น ไม่มีโบนัสย้อนหลัง • ถ้าอัตราเปลี่ยน (ไม่มีตู้เย็นเหลือ) → `storeSync` rebase ทุกกองที่เวลานั้น
- **ตัดผลเดิม**: `hasFridge` ไม่ลดอายุของในกระเป๋าอีก (`freshPub.fz` ส่ง false เสมอ, `market.js:107`, `workshop.js:65` ส่ง false) → ช่องโหว่ (ข) หายเพราะผลมีเฉพาะของที่อยู่ในคลังจริง
- เข้าถึง: เฉพาะเจ้าของ ในบ้านตัวเอง ห่างตู้ชนิดนั้น ≤ 4 ช่อง (เซิร์ฟเวอร์ตรวจทุกครั้ง) คนมาเยี่ยมเปิดไม่ได้ • ปุ่ม Action (Space/A) ที่ตู้ใกล้สุด = เปิด • แตะตู้ = เปิด/เดินไปก่อน (แบบเก้าอี้ `houseIsoClick`)
- UI: แผงเดียวสองคอลัมน์บน PC (คลัง | กระเป๋าที่เข้าคลังนี้ได้) มือถือเป็นแท็บ "ในตู้ / ในกระเป๋า" แต่ละแถว `.row` = ไอคอน ชื่อ จำนวน ป้ายสด 🟢🟡🔴 ปุ่ม [1] [ทั้งหมด] • ปุ่มรวม "เก็บของสดทั้งหมด" / "หยิบทั้งหมด" • หลอดความจุ `ใช้ 41/120` • ปุ่ม ≥44px ที่ 360×640 • Space ยืนยันรายการที่โฟกัส, Esc ปิด
- **ห้ามของหาย**: ถอดตู้ได้เฉพาะเมื่อความจุที่เหลือ ≥ ของในคลัง ไม่งั้นเตือน "หยิบออกก่อน/วางตู้เพิ่ม" • ตู้ถูกคืนตอนโหลด (ข้อมูลเสีย `house.js:14`) → ของอยู่ในคลังต่อ (เกินจุ = หยิบได้อย่างเดียว ไม่เย็นถ้าไม่มีตู้เย็น) • ขายตู้ที่ยังไม่ได้วางได้ปกติ (ของไม่ได้อยู่ในตัวตู้)
- ซื้อขาย/เทรด/แผง/สูตรช่าง ใช้ของในกระเป๋าเท่านั้น ต้องหยิบออกก่อน (แหล่งความจริงเดียว ไม่ต้องแก้ทุกทางขาย) • แผงตลาดไม่นับตู้เย็นเหมือนเดิม

## 4. ผลเฟอร์นิเจอร์ (B) — ไม่บังคับ มีเพดาน ไม่แตะเหรียญ/XP
- **ความสบาย (comfort)** คิดจาก *ชนิดไม่ซ้ำ* ที่วาง: ชิ้นละ 1 (ราคา ≥900 = 2, rare = 3) รวมต่อหมวด FURN.cat แล้วตัดเพดานหมวด (living/bedroom/kitchen/decor 6, study/craft/rare 4, divider 2) → สูงสุด 38 • ขั้น: 0–5 โล่ง • 6–13 อยู่สบาย • 14–23 อบอุ่น • 24+ บ้านในฝัน (วางต้นไม้ 300 ต้นไม่ช่วย มูลค่าไม่ใช่ตัวตัดสิน)
- ผลในบ้าน (คนที่นั่ง/นอนในบ้านหลังนั้น รวมคนมาเยี่ยม): นั่ง/นอนฟื้นอิ่ม `sitGain` ×1 / ×1.5 / ×2 / ×2.5 ตามขั้น (ขั้น 0 = เท่าเดิม ม้านั่งในเมืองไม่เปลี่ยน)
- ผลพกติดตัว (บ้านตัวเองเท่านั้น): นอนเตียงต่อเนื่อง 60 วิ → บัฟ 😴 **หลับสบาย** หิวลดช้าลง 25% นาน 0/15/25/35 นาทีตามขั้น ไม่ซ้อน ต่อเวลาใหม่ได้แต่ไม่สะสม ไม่ซ้อนกับ `BUFFS.hunger` (ใช้ตัวที่แรงกว่า) • กรอบ: ประหยัดได้ไม่เกิน ~1 มื้อ/รอบนอน
- **ชุดห้อง** (โชว์ความคืบหน้า "ครัว 2/3 ขาดเตาแก๊ส"): 🍳 ครัว (fridge+stove+counter/sink) = กินในบ้านอิ่มเพิ่ม +20% • 🛏️ ห้องนอน (เตียง+nightstand/dresser/wardrobe+โคมไฟ) = บัฟหลับสบายนาน ×1.5 • 🛋️ นั่งเล่น (ที่นั่ง+coffeetable/table+tv/fireplace/piano) = ขั้นความสบาย +1 สำหรับการนั่ง • 📚 มุมอ่าน (desk+officechair+shelf/computer/globe) = ความสบาย +2 (ไม่ให้ XP ดูคำถาม 7)
- การโชว์: การ์ดร้านเฟอร์นิเจอร์มีป้ายผล (`❄️ คลังเย็น +60` `📦 คลังของ +80` `✨ สบาย +1` `🍳 ชุดครัว`) • ในบ้านมีชิป `🏠 สบาย 14 · อบอุ่น` แตะ/Action ดูรายละเอียด: ผลตอนนี้ ขั้นถัดไปขาดอะไร ชุดห้อง • ข้อความทั้งหมดอยู่ใน `HOME` (shared)

## 6. ข้อความ (client↔server) — ระบบ storage เป็นเจ้าของ `store`
| type | ทิศ | ฟิลด์ | ตรวจ |
|---|---|---|---|
| `store` a:`open` | C→S | `i` (id เฟอร์นิเจอร์) | ในบ้านตัวเอง, ชิ้นนั้นเป็นตู้ใน `HOME.store`, ระยะ ≤4 ช่อง, เว้น 150ms → ตั้ง `p.storeAt={pool,i}` |
| `store` a:`put`/`take` | C→S | `pool`, `k`, `n` (จำนวนเต็ม ≥1) | `p.storeAt` ตรง pool และยังอยู่ในระยะ, `S.storeAccepts(pool,k)`, มีของพอ, ความจุ (put) • ทำผ่าน `add()` เพื่อส่ง lots |
| `store` a:`putall`/`takeall` | C→S | `pool` | เหมือนข้างบน ใส่ได้เท่าที่จุ เรียงของเก่าก่อน |
| `store` (ผล) | S→C | `pool cap used inv{k:n} l{k:[[tv,n]]} r at` | ส่งหลังทุกคำสั่ง + `inv` เดิมจาก `add()` |
| `hcomfort` | S→C | `v tier sets[] rest` | ตอนเข้าบ้าน/วาง/ถอด • `HOUSE_MSG` เพิ่ม `store` |

## 7. จุดต่อลิมิตถือตัว (D) — ไม่ทำตอนนี้

## 8. เซฟ + ย้ายข้อมูล (ไม่ bump xpv เพิ่มแบบ additive)
- `rec.store = { cold:{inv,lots,r,at}, box:{inv} }` (สร้างเมื่อใช้ครั้งแรก) • `rec.rest` = เวลาหมดบัฟ • `rec.frz = 1` = ย้ายตู้เย็นเดิมแล้ว (บัญชีใหม่สร้างพร้อม `frz:1`)
- ย้ายครั้งเดียวตอนโหลด (หลัง `loadHouse`): บัญชีที่ไม่มี `frz` และมีตู้เย็นวางอยู่ → กองในกระเป๋า `t' = now − (now − max(t,startAt)) × 0.5` (ความสดที่เห็นไม่กระโดด) แล้วตั้ง `frz=1` • ทำซ้ำไม่ได้ • log จำนวนบัญชี • ไม่ย้ายของเข้าตู้ให้เอง แจ้ง toast ครั้งเดียว "ตู้เย็นเก็บของได้จริงแล้ว"
- สำรอง: `cp data/main.json backup/` ก่อน deploy ตาม `docs/OPS.md` • ถอยโค้ด: โค้ดเก่าไม่รู้จัก `rec.store` ของจะ "มองไม่เห็นแต่ไม่หาย" → รัน `tools/store-unstash.js` (ใหม่ ปิดเซิร์ฟเวอร์ก่อน) ย้ายของในคลังทั้งหมดกลับกระเป๋าพร้อมแปลงอายุ แล้วค่อยถอยโค้ด

## 11. คำถามให้เจ้าของตัดสิน (ข้อเสนอเริ่มต้นในวงเล็บ)
1. ตัดผล "ตู้เย็นในบ้านชะลอของทั้งกระเป๋า" แล้วให้ชะลอเฉพาะของในตู้แรงขึ้น (ตัด, ในตู้ ×0.25)
2. ความจุนับเป็น ชิ้น หรือ ช่องชนิด (ชิ้น: ตู้เย็น 60 สูงสุด 4 ใบ, ลังไม้ 80 คลังของสูงสุด 6 ใบ)
3. หีบ/ลังรับของสดไหม (ไม่ ของสดต้องตู้เย็น)
4. เปิดคลังจากนอกบ้านได้ไหม (ไม่ เฉพาะในบ้านตัวเองใกล้ตู้)
5. ทำตู้เสื้อผ้าเก็บชุดรอบนี้ไหม (เลื่อนไปหลังลิมิตถือตัว)
6. คนมาเยี่ยมได้ผลนั่งสบายของบ้านนั้น / บัฟหลับสบายเฉพาะเตียงบ้านตัวเอง (ใช่ / ใช่)
7. มุมอ่านหนังสือให้ XP เล็กน้อยไหม (ไม่ ไม่แตะ XP/เหรียญ)
8. ลีดเดอร์บอร์ดบ้านเพิ่มคอลัมน์ความสบาย (เพิ่มคอลัมน์ ยังเรียงตามมูลค่าเดิม)
