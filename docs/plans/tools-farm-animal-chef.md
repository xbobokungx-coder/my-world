## 2. กลไกกลาง (ทั้งหมดใน `public/shared.js`)
- **อุปกรณ์แบบติดตัว (passive):** ไม่ต้องถือ ทำงานเมื่อมีในกระเป๋าและความทน > 0 • ระดับ 1 แจกฟรีทุกคน (แบบคัน 1) • พังแล้ว**ไม่บล็อก**การเก็บ/ทำอาหาร แค่ไม่ได้โบนัส = เกมเดิมพอดี (พื้นล่าง = ตัวเลขปัจจุบัน ไม่มีใครรายได้ลด)
- ระดับของไอเทม: `cropTier(c) = ⌈c.lv/2⌉` • `animalTier(A) = ⌈A.lv/2⌉` • `cookTier(r) = ⌈r.lv/2⌉` • `d = ระดับอุปกรณ์ − ระดับไอเทม`
- `S.gearHit(tool, tier, itemTier)` → `{ d, bonus, wear }` ตาม `GEAR_TUNE[tool]`: d ≥ 0: `bonus = min(over.cap, base + over.bonus×d)`, `wear = 1/(1+over.wear×d)` • d < 0: `k = max(0, 1 + under×d)`, `bonus = base×k`, `wear = k` (ต่ำ 4 ระดับ = ไม่มีผล ไม่สึก) **กฎ: กำไรสุทธิต้องไม่ลดลงเมื่ออัประดับ และไม่ต่ำกว่าพื้น** (ห้ามใช้ wear ×(1+0.5×ขาด) แบบขวาน เพราะทำให้ระดับต่ำกว่าแย่กว่าไม่มี)
- `GEAR_TUNE = { hoe: { base: 0.13, under: 0.25, over: { bonus: 0.03, cap: 0.25, wear: 0.25 } }, pail: { base: 0.25, under: 0.25, over: { bonus: 0.03, cap: 0.40, wear: 0.25 }, max: 0.75 }, pan: { base: 0.10, under: 0.25, over: { bonus: 0.02, cap: 0.15, wear: 0.25 }, minFee: 0.15 } }`
- ตัวห่อ: `hoeBonus(inv, crop)` = โอกาส +1 พืช • `pailChance(inv, A)` = `min(max, ANIMAL_BONUS + bonus)` (ANIMAL_BONUS 0.25 คงไว้เป็นพื้น) • `panFee(r, tier, ok)` = `max(minFee, COOK_FEE − bonus)` (ok=false → COOK_FEE เดิม 0.3) ใช้ทั้งเซิร์ฟเวอร์และหน้าเว็บ
- ตาราง/ฟังก์ชัน: `GEAR_MAX = 10`, `HOES/PAILS/PANS` สร้างด้วยลูปแบบ `AXES` (shared:421–425), `CANS` 10 แถว, `canTier` เป็นลูป, `hoeTier/pailTier/panTier` (ไม่มีคีย์ = 1), `HOE_EMOJI/PAIL_EMOJI/PAN_EMOJI` + อีโมจิใน `CANS` • `DURABILITY.hoe/pail/pan` (shop farm/animal/food) และ `TOOL_PRICE.hoe/pail/pan` 11 ช่อง (ช่อง 1 = ราคาซื้อใหม่ของระดับฟรี) • `fix` = round(ราคา×0.25) แสดงผลเท่านั้น

## 8. ทางเลือกให้เจ้าของรีวิว (ค่าที่เลือก = A)
- **A (เลือก):** อุปกรณ์ติดตัว พื้น = เกมปัจจุบัน ตรงระดับได้สุทธิ ~+5% ไม่ต้องย้ายเซฟ ไม่มีใครรายได้ลด • ข้อเสีย: แรงจูงใจอัปอ่อน (ไม่อัปเสียสูงสุด ~5%) ไม่ใช่ 55–94% แบบขวาน เพราะงานเหล่านี้ไม่มีด่านบล็อก • เพิ่มแรงจูงใจได้ด้วย `GEAR_TUNE.*.base` (เช่น จอบ 0.20 ≈ +10%) แต่อาชีพอื่นจะดู % ต่ำลงเท่ากัน
- **B แบบบังคับ:** ไม่มี/พัง = แย่กว่าวันนี้ (ANIMAL_BONUS 0.10, ค่าเตา 0.40) ต้องแจกระดับตามเลเวลให้คนเดิมด้วย xpv 8 (ล็อกขายคืนด้วย tmig) = ใกล้ขวานแต่ผู้เล่นรู้สึกถูกลด
- **C บัวเปียกนานขึ้น:** ชาวนา Lv13+ +20% ทันที ต้องลดราคาพืชชดเชย • **D เชฟทำเร็วขึ้น:** ทำให้โหมดซื้อวัตถุดิบที่เกินเป้าอยู่แล้ว (109–342%, WP-22) แย่ลง • **E สัตว์หิวช้า:** levelsim ไม่เห็นผลทางเงิน (ป้อนตามรอบผลิต) ทำทีหลังเป็นความสะดวกได้ • **F บัวมีความทน:** เพิ่มงานซ้ำซ้อนกับตักน้ำ จึงให้ค่าสึก 8% อยู่ที่จอบอย่างเดียว (ผิดจากคำสั่ง "ทุกชิ้นมี DURABILITY" ข้อเดียวนี้)

## 9. ความเสี่ยงและการถอยกลับ
- **ตัวหารขยับ:** ชาวนา +G → ประมง/ไม้/เหมืองดู % ต่ำลง ~G จุด (ไม้ Lv11+ ต่ำอยู่แล้ว) • **สัตว์ (WP-21):** เพดานการกระทำทำให้ตะกร้าเพิ่มเงินตรงๆ ช่วงต้นที่ค่าอาหารสูง G อาจถึง ~15% → E1 อาจต้องตั้ง base ตามระดับ • **เชฟ (WP-22):** ลดค่าเตาดันโหมดซื้อขึ้น • **FARM_CAP:** จอบ/บัวไม่เพิ่มจำนวนต้น บัวไม่ข้ามเพดาน • **พืช (WP-20):** จอบสูงกว่าพืช +3%/ระดับ อาจทำ levelsim เลือกพืชถูกแทน ดูคอลัมน์ pick
- **ช่องโกง:** ขายคืนแล้วซื้อใหม่ (แก้ใน S2) • ซื้อระดับต่ำรีเซ็ตความทน (กันใน S2) • หลายบัญชี: ของ `once` เทรด/ฝากขายไม่ได้ (`isTradable` shared:1572) ตะกร้าได้ผลเฉพาะสัตว์ที่ตัวเองป้อน • เก็บผลผลิตของคนอื่นหลัง 1 วันไม่ได้โบนัสตะกร้า
- **ถอยกลับ:** `git revert` ได้ทันที (ไม่เปลี่ยนรูปแบบเซฟ) ข้อจำกัด: คนที่ซื้อ can_4+ แต่ไม่มี can_3 จะปลูก Lv6+/Lv8+ ไม่ได้ในโค้ดเก่า และเหรียญที่จ่ายของใหม่ไม่คืน → ประกาศ หรือสคริปต์เสริมเติม can_3 ให้ (ตัดสินตอนถอย) • ข้อมูลเสีย: กู้ `backup/pre-deploy/`
