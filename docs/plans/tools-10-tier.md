## 4. เซฟ: xpv 5 → 6 `S.migrateToolsV6(rec)` (pure, idempotent, ข้ามเมื่อ xpv ≥ 6)
1. หา oldAxe = ระดับสูงสุดใน `axe_1..5`, oldRod = สูงสุดใน `rod_2..7` (ไม่มี = 1) **ก่อน** เพิ่มคีย์
2. ชุดที่ถูกต้อง N = { map[t] : t ที่ถืออยู่ } • เพิ่ม `inv[key] = 1` ให้คีย์ใน N ที่ยังไม่มี • **ไม่ลบ ไม่ลดคีย์เดิม ไม่แตะ coin**
3. คีย์เดิมที่ไม่อยู่ใน N = ของค้างจากการแปลง บันทึกใน `rec.tmig = { add: [คีย์ที่เพิ่ม], left: { คีย์: จำนวน }, dur: { axe, rod เดิม } }`
4. ความทน: ถ้า `rec.dur.axe/rod` เป็นตัวเลข → oldMax = floor(oldMax[old]×(1−0.15×min(3,fix))) • ratio = dur/oldMax (ตัด 0–1) • ใหม่ = ratio>0 ? max(1, round(ratio×durMax(tool, map[old], fix))) : 0 • ไม่มีค่า dur = เต็ม ไม่แตะ • `rec.fix` ไม่แตะ
5. `rec.xpv = 6` คืน `{ axe: [old,new], rod: [old,new] }` • loader `server.js:64–74` ต่อโซ่: ทุกทาง (xpv 3, 4, เก่ากว่า) จบด้วย `migrateToolsV6` และเงื่อนไข `>= 5` บรรทัด 66 เป็น `>= 6` + log `[migrate] อุปกรณ์ xpv 6: ย้าย N บัญชี` • ผู้เล่นใหม่ `server.js:174` เป็น `xpv: 6`
6. โค้ดใหม่ถือว่าคีย์ใน `tmig.left` เป็นของเก่า: ขายคืนไม่ได้ (`market.js:107` sellback ใช้ inv−left) และไม่แสดงในกระเป๋า • **ถ้าไม่กันจะเกิดเหรียญฟรี** (sellback 70% ของราคาใหม่)
- **สำรอง:** ก่อน deploy ดึงสำรองนอกเครื่อง + `backup/pre-deploy/` (หัวข้อ 11) ซ้อมกับสำเนาจริงใน `data-dev`
