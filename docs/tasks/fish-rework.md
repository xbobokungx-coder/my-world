# ตั๋ว: ปรับชาวประมง (เส้นเลเวล 20 ชม. เหมือนนักขุดแร่)

เจ้าของสั่ง: เวลาไต่เลเวลพอๆ กับขุดเหมือง (ถึง Lv20 ≈ 20 ชม. Lv1→2 = 15 นาที) และให้ผมแนะนำ/ปรับปรุงระบบทั้งหมดได้ ร่างวิเคราะห์ `docs/plans/fish-rework.md` (ข้อ 1–10 = ปัญหา, A–G = ข้อเสนอ) ใช้ข้อเสนอที่ผมเลือกด้านล่าง
รูปแบบงานเดียวกับนักขุดแร่ ดู `docs/tasks/mine-rework.md` และ `migrateMineV4`/`xpMineV4` ใน `public/shared.js` เป็นแบบอย่าง

## ตัดสินใจแล้ว
- ตารางหลอดมาตรฐานรายเลเวล `XP_TABLE_STD` สะสม Lv1…20 = 0, 0, 250, 576, 1000, 1552, 2271, 3208, 4428, 6017, 8086, 10780, 14289, 18859, 24810, 32561, 42655, 55801, 72921, 95218, 124256 (XP/ชม.จริงเป้า = 1,000 × 1.1412^(เลเวล−1) เวลาต่อเลเวล = 0.25 × 1.1412^(เลเวล−1) ชม.) ชาวประมงใช้ตารางนี้ **ชาวนาและอาชีพอื่นจะใช้ตารางเดียวกันในรอบถัดไป** จึงต้องทำเป็นกลไกทั่วไป ไม่ผูกชื่ออาชีพ
- A3: (ก) พักรอบปลาหายากใช้เฉพาะปลาแพงมาก: เกณฑ์ใหม่ `RARE_SELL` (เริ่ม 400 เดิม 100) ปลา 100–399 ตกได้ปกติไม่ติดพัก (ค่าเริ่ม ให้ economy-designer ปรับ 200–500) (ข) สระปลาเลื่อนตามเลเวล: ปลาเลเวลต่ำกว่าปลาใหม่สุดที่ผู้เล่นตกได้เกิน `FISHPOOL.keep` ระดับ ถูกลดน้ำหนัก ×`FISHPOOL.decay`^(ส่วนที่เกิน) (เริ่ม keep 2 decay 0.75) → ปลาใหม่ตกบ่อย ไม่ใช่ของหายากตลอด
- ปลาทะเล (`sea: true`) ใช้กลไกและตารางหลอดเดียวกับน้ำจืด นับเข้าเส้นเดียวกัน
- ดาวความชำนาญ `MASTERY.xpPerSkill.fish` = 8000 (≈ 28% ของหลอดสุดท้าย แบบนักขุดแร่)
- ตะเกียง/อื่นๆ ไม่เกี่ยว

## ขอบเขตรอบนี้ — server-dev (`public/shared.js`, `server.js`, `server/systems/fishing.js`, `server/systems/core.js` ที่เกี่ยวข้อง)
1. กลไกตารางรายอาชีพทั่วไป: `XP_TABLES = { mine: XP_TABLE_MINE, fish: XP_TABLE_STD }` และ `xpTable(skill)` ดูจาก XP_TABLES (ไม่มี = ตารางเดิม) เพื่อให้เพิ่มอาชีพต่อไปด้วยบรรทัดเดียว `levelOf`/`xpFor` ยังรับ skill เหมือนเดิม • ตรวจผู้เรียกทุกที่ส่ง skill ครบ (โดยเฉพาะ `playLevel` ซึ่งแก้แล้วให้ส่ง skill, เกณฑ์ที่ผูก `playLevel`, ดาวความชำนาญ, ปุ่มผู้ดูแลปรับเลเวล)
2. ตัวย้ายเซฟทั่วไป (`rec.xpv` 4 → 5): pure `xpStdV5(xp, skill)` แปลง XP ตาราง `XP_TABLE` เดิม → `XP_TABLE_STD` เลเวลเท่าเดิมและสัดส่วนความคืบหน้าเท่าเดิม (เกิน Lv20 ปรับตาม `masteryXp(skill)/MASTERY.xpPer` เหมือน `xpMineV4`) และ `migrateStdV5(rec, skills)` รับรายชื่ออาชีพ (ตอนนี้ `['fish']` — ชาวนาเพิ่มภายหลังโดยใส่ชื่อเดียว) idempotent (ข้ามถ้า `xpv >= 5`) ไม่พังถ้าไม่มี `skills` • ต่อโซ่ใน `server.js` ตอนโหลดเซฟ (xpv 4 → 5 ต่อจาก `migrateMineV4`) ผู้เล่นใหม่เริ่ม `xpv: 5` • log สรุปรวม `[migrate] ... xpv 5: ย้าย N บัญชี` • ไม่ต้องย้ายคันเบ็ด (คีย์ `rod_N` เหมือนเดิม) ถ้าปรับความทนทานเบ็ดภายหลังให้ `economy-designer` แจ้ง
3. `MASTERY.xpPerSkill.fish` = 8000
4. A3 (ก): ค่าคงที่ `RARE_SELL` ใน shared.js ใช้แทนเลข 100 ที่เป็นเกณฑ์พักรอบ (`fishing.js` บรรทัด ~73 ตรวจพัก และ ~98 ตั้งพัก, ป้ายพักรอบ/ข้อความที่อ้าง 6 นาทีหรือราคา 100, `levelsim.js`) **แต่คงเลข 100 ใน `fishWeight` ที่เป็นโบนัสความถี่ปลาแพงตามเลเวล/เบ็ด และ `fishClass`** (ไม่ใช่เกณฑ์พักรอบ) ตรวจให้ครบ grep `>= 100` `≥ 100` ใน shared/server/public/tools
5. A3 (ข): `FISHPOOL = { keep: 2, decay: 0.75 }` ใน shared.js และ `fishWeight` คูณตัวลดน้ำหนักตามระดับห่างจากปลาใหม่สุดที่ผู้เล่นตกได้ (นับเฉพาะปลาชุดเดียวกัน น้ำจืด/ทะเล ตามเลเวลชาวประมงและเบ็ด) ให้ pure และมีเทสต์
6. ไม่ต้องปรับ `FISH[].xp` / ราคาเบ็ด / ความทนทาน / เหรียญ — `economy-designer` จะปรับต่อ (ใส่ค่าชั่วคราวให้รันได้)
