# ตั๋ว: ย้ายความทนทานเบ็ด/ขวาน/อีเต้อ ตามสัดส่วน (ไม่มีใครเสียสิทธิ์)

เจ้าของเกมอนุมัติ: ย้ายตามสัดส่วนตอนโหลดเซฟครั้งเดียว (14 พ.ย. 2026) ห้ามเปลี่ยนตัวเลข DURABILITY.max ที่ economy-designer ตั้งไว้แล้ว

## ปัญหา
`DURABILITY.max` ของ rod/axe/pick ใน `public/shared.js` เปลี่ยน แต่ `rec.dur.<tool>` เก็บเป็นหน่วยสัมบูรณ์ และ `durCur` (server/systems/tools.js:12) แค่ clamp ด้วย max ใหม่
- rod ระดับ 4–10 (max ลด): ชิ้นที่ใช้น้อยถูกตัดลง (คัน 10 เต็ม 2900 → 2325)
- axe/pick (max เพิ่ม): ชิ้นเต็มเดิมกลายเป็นไม่เต็ม (ขวาน 10 เต็ม 2610 → 79% ของ 3315) ราคาขายคืนตกจาก 70% เป็น ~55% และมีค่าซ่อมก้อนหนึ่ง

## ที่ต้องทำ
1. migration ครั้งเดียวตอนโหลดเซฟผู้เล่น: `dur_ใหม่ = round(dur_เก่า / oldMax[tier] × newMax[tier])` ต่อเครื่องมือที่ถือ (rod/axe/pick) โดยคงสัดส่วนความสึก ชิ้นที่ dur ยังไม่เคยมีค่า (undefined = ใหม่เต็ม) ไม่แตะ ระวังจำนวนครั้งซ่อม (REPAIR: durMax ลดตามจำนวนครั้งซ่อม) ให้ตัดตัวคูณ (1 − decay × fixes) ออกเมื่ออัตราส่วนเดียวกัน หรือคำนวณ max ทั้งสองแบบให้ตรงกับ `durMax(tool, tier, fixes)` จริง และ clamp 0..newMax ผลต้องเป็นจำนวนเต็ม ไม่ NaN/ติดลบ
2. ต้อง idempotent: รันซ้ำไม่ย้ายซ้ำ เลือกวิธีตามรูปแบบเดิม `migrateToolsV6` / `migrateMineV4` ใน shared.js (ค่าสถานะใน rec เช่น xpv หรือธงใหม่ เลือกอย่างใดอย่างหนึ่งตามที่โค้ดเดิมทำและรายงานว่าเลือกอะไรเพราะอะไร ถ้าใช้ xpv ต้องไม่ทำให้ migration อื่นที่ผูกกับ xpv พัง) เซฟที่ไม่มีเครื่องมือเหล่านี้ไม่เปลี่ยน
3. ถอยกลับได้: เพิ่ม/ปรับ `tools/tools-unmigrate.js` ให้คืนสัดส่วนกลับเป็นตารางเก่า (ประมาณ) แล้วระบุใน docs/OPS.md สั้นๆ ว่าต้องรันก่อนย้อนโค้ด
4. ซ้อมกับสำเนาเซฟจำลองใน data-dev/ในเทสต์เท่านั้น ห้ามอ่าน/เขียน data/ จริง
5. เทสต์ใหม่ (เช่น tools/test-dur-migrate.js): ชิ้นเต็มเดิมยังเต็ม, ชิ้นครึ่งหนึ่งยังครึ่งหนึ่ง, ชิ้นผ่านการซ่อมหลายครั้ง, ชิ้นที่ dur=0, รันซ้ำไม่ย้ายซ้ำ, เซฟไม่มีเครื่องมือไม่พัง, ราคาขายคืนชิ้นเต็ม = 70% เท่าเดิมของทุกชิ้น, ผ่าน unmigrate กลับมาใกล้ค่าเดิม (ยอมคลาดจากการปัดเศษ) และ test-rod-migrate / test-axe-migrate / test-gear* เดิมยังผ่าน (ถ้าเทสต์ล็อกค่าที่ migration ใหม่เปลี่ยนโดยตั้งใจ ให้ปรับให้ตรง ไม่ใช่ข้าม) golden ต้องไม่เปลี่ยนนอกจากที่จำเป็น แจ้งส่วนต่าง
6. อัปเดตรายงาน docs/reports/durability-balance-2026-11-14.md หัวข้อ "ผลต่อเซฟเก่า" ให้ตรงกับการย้ายใหม่ และ ECONOMY-PLAN.md change log หนึ่งบรรทัด
