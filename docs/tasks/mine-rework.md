# ตั๋ว: ปรับนักขุดแร่ (ถ้ำเหมือง)

แผนล็อกแล้วอยู่ที่ `docs/plans/mine-rework.md` — **อ่านทั้งไฟล์ก่อน โดยเฉพาะหัวข้อ "แก้ล่าสุด 20 ชม." และ "ตัดสินใจเพิ่ม" ท้ายไฟล์ (ใหม่กว่าเนื้อหาด้านบน)**
เจ้าของอนุมัติแล้ว: ตะเกียงคงไว้ • ชุดอุปกรณ์ 10 ชนิด • ย้ายเซฟผู้เล่นเดิม

## ขอบเขตรอบนี้ (server-dev) — `public/shared.js`, `server/systems/mining.js`, `server/systems/core.js`, ที่ที่เกี่ยวข้อง
1. บันไดลงเหลือ 1 ช่อง (`makeCaveMap`) + ตรวจ `mining.js:25,70` และโค้ดที่หา/วางตำแหน่งบันได
2. `PICKS` 10 ชนิด คีย์ `pick_1..10` ชื่อ: ถุงมือ • จอบไม้ • อีเต้อเหล็ก • ค้อนทุบหิน • ชะแลง • สว่านมือ • สว่านลม • สว่านไฟฟ้า • ไดนาไมต์ • ระเบิด (ปลดที่ Lv1,3,…,19 ตามแร่) `ORES[k].pick` = ลำดับแร่ 1..10 • power = เลขระดับ • ราคา 60/260/600/1100/1900/3000/4500/6500/9000/12500 ใน `PICKS` + `TOOL_PRICE.pick` + `DURABILITY.pick.max` (ขยายเป็น 10 ช่อง ความทนทานไล่ตามราคา) • `pickTier` วนถึง 10 • `PICK_EMOJI` ขยาย (คีย์ไอคอนใหม่ client-dev/pixel-artist ทำตามหลัง ตอนนี้ใส่ชื่อคีย์ชั่วคราวที่ไม่ทำให้เว็บพัง)
3. ลบ `GLOVES` `HAMMERS` `gloveTier` `hammerTier` + สินค้า `glove_*` `hammer_*` ใน `SHOPS.mine.buy` และ `itemInfo` ตัดตัวคูณจาก `mineHit` • ตะเกียง `lamp` คงไว้
4. `mineHit`: ต่ำกว่าแร่กี่ระดับก็ขุดได้ (ลบ `d < -1 → null`) • ดาเมจ = `power × MINE.slow.dmg^|d|` (เริ่ม 0.85) การสึก `1 + 0.5|d|` เท่า • เพดานจำนวนฟาด `MINE.maxHits` 120 • ด่านเลเวลของแร่ (`ORES[k].lv`) ยังอยู่ • `minHits` คงไว้
5. ชิ้นโบนัส (อีเต้อสูงกว่าแร่) ได้ XP: `mining.js:129` นับ `O.xp × (n + โบนัส)`
6. XP นักขุดแร่ใหม่ (ค่าจากแผน): `ORES[].xp` = หิน 3.6 • ทองแดง 4.8 • เงิน 6.7 • อเมทิสต์ 7.9 • มรกต 11.6 • โอปอล 13.1 • ไพลิน 19.3 • หยก 21.9 • มูนสโตน 32.2 • มิทริล 39.6 • **เอา `MINE.xpPerLv` (ตัวคูณเลเวล) ออก** (`oreXp` คืนค่าเดิม)
7. ตารางหลอดรายอาชีพ: เพิ่ม `XP_TABLE_MINE` สะสม Lv1…20 = 0, 0, 250, 535, 959, 1442, 2158, 2976, 4189, 5573, 7627, 9970, 13447, 17415, 23301, 30018, 39983, 51355, 68225, 87477, 116038 • `levelOf(xp, skill)` และ `xpFor(lv, skill)` รับ skill (ไม่ส่ง = ตารางเดิม) แก้ผู้เรียกทุกที่ (`core.js:116-122`, `achievements.js:41` ดาวความชำนาญ, `game.js:56,1189,1190,1225` ให้ client-dev แก้ในรอบถัดไป แต่ถ้าแก้ง่ายและไม่ทับกัน ทำให้เลย) • ดาวความชำนาญ (`MASTERY.xpPer` 25,000/ดาว) ของนักขุดคิดจากตารางใหม่: เสนอค่าที่สัดส่วนกับหลอดสุดท้าย แล้วแจ้งในรายงาน
8. **ย้ายเซฟ** (`rec.xpv` 3 → 4 เฉพาะ `skills.mine`; ถ้าเซฟไม่มีฟิลด์นี้ ดูรูปแบบที่ `xpFromV2` ทำไว้): XP นักขุดเดิม → ตารางใหม่ เลเวลเท่าเดิมและสัดส่วนความคืบหน้าเท่าเดิม (ตัวแปลงเป็น pure function ใน shared.js มีเทสต์) • อีเต้อ `pick_1..6` → ใหม่ 1→1, 2→2, 3→4, 4→6, 5→8, 6→10 (แปลง `rec.inv` และ `rec.dur`/จำนวนซ่อม ให้ความทนทานคงสัดส่วน) • ถุงมือ `glove_*` ค้อน `hammer_*` ในกระเป๋า: ลบ + คืนเหรียญเท่าราคาซื้อเดิม (ถุงมือ 220/1200/4000 ค้อน 600/2500/7000) ตามเลเวลที่ซื้อได้ (ที่มีอยู่จริงเท่านั้น) ผ่านฟังก์ชันย้ายตอน load ครั้งเดียว (idempotent) • **ห้ามอ่านหรือแก้ `data/` จริง** ทดสอบกับเรคอร์ดสังเคราะห์
